# Punk Bridge v3

This service replaces the unauthenticated v2 bridge after a coordinated cutover. It never modifies or stops the previous `punk_server.py` automatically. Python 3.11+ is required. The implementation uses the API and plugin contracts present in the locally installed Hermes `0.22.0+141.g9f3f833.dirty`; other versions require compatibility verification.

On Windows, the helper scripts use the Python interpreter at `%LOCALAPPDATA%/hermes/hermes-agent/venv/Scripts/python.exe`. Install `requirements.txt` in that environment before provisioning, or use a dedicated environment and invoke `server.py` / `pair.py` directly. The provisioning helper needs access to the installed native Hermes checkout. Pairing QR generation requires `qrcode` and Pillow, included in the requirements.

## Provision and start

For an already provisioned Windows installation, double-click **ABRIR-PUNK.vbs** in the repository root. Punk Desktop shows PC/phone/Hermes/ADB health and provides connection and expiring QR buttons without opening a terminal. It uses the existing Hermes Python environment. Closing the dashboard leaves the bridge running. This is not yet a standalone installer; see [the Desktop/MCP design](../docs/PUNK-DESKTOP-MCP.md).

Version 3.6 adds managed Neon login and optional free Cloudflare Quick Tunnels. Create/sign in to the same account on Desktop and Android, enable external access on Desktop, then select the PC on Android. No purchased domain or manual token copying is required. Public service URLs are shipped in `core-bridge/src/main/assets/punk-account.json`; all private state stays under ignored `runtime/`. [Account setup, privacy and free-tier limits](../docs/CONTA-PUNK.md).

1. Run `python setup_hermes.py` to review the dry run. With `--apply`, the native Hermes profile API creates `punk-mobile`, synchronizes the default identity/model/skills/plugins and gives the API channel the same toolset configured for Telegram. It installs `punk_control`, provisions distinct loopback credentials and keeps conversation history, channel credentials, cron state and secrets profile-local. The default profile receives only the listener credential required by the native API; Telegram/WhatsApp credentials and policies are not changed. No model/device call or automatic service restart occurs.
2. Coordinate restarting/rescanning the existing Hermes gateway so its native API serves `http://127.0.0.1:8642/p/punk-mobile`. Do not run a second writer against the default Hermes home. The bridge rejects chat until the policy plugin heartbeat is live. Durable external memory configuration remains identical to the default profile.
3. After provisioning, run `INICIAR-PUNK.ps1` on Windows. It synchronizes identity, configuration and skills again before starting, writes a non-secret diagnostic to `runtime/identity-sync.json`, then opens **18765 (TLS)** and **18766 (loopback only)**. For manual startup, run `clone_profile.py --status-file runtime/identity-sync.json` first and then `python server.py --port 18765 --internal-port 18766`. A busy port fails; no process is killed. Keep the plugin settings and runtime configuration on the same ports.
4. Run `PAREAR-PUNK.ps1` on the PC to open a local page containing a one-use QR valid for five minutes. The page and `runtime/pairing.json` contain a temporary secret; never commit or share them. The lower-level `python server.py --pair --advertise-host SAME_ADDRESS` prints a pairing JSON for manual workflows. The payload includes the SHA-256 certificate pin. A certificate change requires explicit re-pairing; never silently trust a new pin.

Runtime secrets/certificate key/SQLite/files live in ignored `runtime/`. Protect that directory with the Windows user ACL (the service sets restrictive Unix mode bits, which alone do not enforce Windows ACLs). Back up privately. Device credentials are SHA-256 digests in SQLite; router/provider keys never enter public pairing payloads. Public access logs are disabled, and errors omit exception bodies. Uploaded original bytes and full chat histories remain private local data; deleting a conversation/file is currently a local maintenance operation. There is a 512 MiB per-file cap; configure disk retention/quota before sharing this service with additional users.

The authenticated health payload also reports whether this PC sees an Android device through ADB. The bridge discovers `adb` from `PATH`, `ANDROID_SDK_ROOT`, `ANDROID_HOME` and the usual per-user SDK folders, then returns only the connection state and device count—never the serial. While the app is connected, it refreshes this status every ten seconds. `unauthorized` means the phone still needs to accept the PC's RSA key; `disconnected` means `adb devices` has no entries.

## Policy

Autonomous is the default, bounded by device-granted capabilities. Supervised mode is a **Punk Mobile channel policy**, implemented independently of Hermes YOLO. The isolated profile's execution middleware checks a local policy broker before dispatch, so native `approvals.mode: off` cannot bypass it. Only an explicit tool-name allowlist is treated as read-only; arbitrary terminal/code/browser evaluation and unknown tools require approval. Explicit detached/background work and delegation are refused while supervised. Approval is one-use and bound to the waiting invocation and original arguments, not a tool-name-wide grant. Declining, timeout, loss of broker health or a policy error blocks dispatch. The middleware never lets its own exception escape into Hermes' fail-open middleware chain. The phone dispatcher remains authoritative for Android tool approvals, avoiding duplicate PC dialogs for `jarvis_*` wrappers.

Switching to supervised immediately gates new actions and cancels previous run work before acknowledging completion. A cancellation failure produces an honest pending/error state. An approved shell/code block is a single action: the bridge cannot supervise individual OS operations inside it, reverse already completed actions, or promise protection from hostile same-user code modifying its own control files. It is an operational consent mechanism, not an OS sandbox. Supervision cannot claim to cover independently scheduled services/processes created before the change.

## Checks

Run `python -m unittest discover -s tests -v` from this directory. Tests use temporary SQLite/files and local mock HTTP servers; they do not start Hermes, invoke an LLM, execute PC automation, or contact a phone. The protocol is specified in [PROTOCOL.md](PROTOCOL.md).
