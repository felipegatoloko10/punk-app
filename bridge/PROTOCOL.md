# Punk Bridge v3

Public base: `https://HOST:18765`; WebSocket `wss://HOST:18765/punk-bridge`.
Pin SHA-256 of the DER leaf certificate from the pairing payload. Never disable certificate verification without also enforcing that exact pin. JSON envelopes remain `{id,type,payload}`. Bearer device token is required for HTTP and WS, except pairing. Never send a token in hello.

## Pairing

PC pairing command prints `{version:3,host,port,useTls:true,certificateFingerprint,pairingCode}`. Fingerprint is lowercase hex (64 characters, no separators). Code expires after 5 minutes, one use. `POST /api/pair` body `{code,deviceName?}` returns `{deviceId,token,protocolVersion:3}`. Invalid/expired/reused code: 401. Persist credentials in Android Keystore. Subsequent requests use `Authorization: Bearer TOKEN`.

## WebSocket

- Client `hello`: `{protocolVersion:3,deviceId,tools:[{name,description?,risk?,schema?}],lastSeq?:0}`.
- Server `hello_ack`: `{protocolVersion:3,deviceId,authenticated:true,supervised:false,health:{bridge:true,hermes:boolean,policy:boolean,identity:{profile,provider,model,toolsetParity,ok},adbState,adbDevices,voiceLive},lastSeq}`. Wrong device or version closes 1008. Only one active socket per device.
- Client `chat`: `{conversationId,messageId,text,spoken?:false,attachments?:[{uploadId,name,mime}]}`. UUIDs generated by client. Duplicate messageId replays persisted events, never starts another run.
- Server `chat_chunk`: `{conversationId,messageId:'assistant:'+userMessageId,requestId:userMessageId,text,done,status,seq,runId?}`. `text` is a delta until done. Final chunk has empty text; statuses `running|completed|failed|cancelled|interrupted`. Optional `error` contains a safe user-facing error.
- Server `task_event`: `{id,title,detail,device:'pc'|'phone',status,ts,conversationId?,seq}`. Status `running|completed|failed|cancelled|waiting`.
- Server `approval_request`: `{id,tool,description,device:'pc'|'phone',conversationId?,expiresAt,seq}`.
- Client `approval_response`: `{id,allow:boolean}`. Authorizes exactly one pending invocation with the original arguments. Late/reused decision has no effect.
- Client `control_mode`: `{supervised:boolean}`. Server acknowledges with `control_mode`: `{supervised,applied:true,seq}` only after cancelling active work when enabling supervision. On failure returns `error` and mode remains conservatively supervised. Default is autonomous within granted device capabilities. Mode applies only to Punk Mobile executions.
- Client `cancel`: `{conversationId}`. Interrupts that conversation's active Hermes run and sends phone `cancel_tools` `{conversationId,callIds:[...]}`. Android must cancel registered tool jobs and acknowledge `cancel_ack` with the same payload; final chat status follows Hermes settlement.
- Server `tool_call`: `{callId,tool,params,conversationId?,supervised}`. Android is the authoritative gate for phone tools, always checking local granted capabilities and the origin's mode. The PC policy middleware delegates `jarvis_*`/`punk_device_*` wrappers to that gate and does not present a duplicate approval. No name-only approval bypass is accepted.
- Client `tool_result`: `{callId,ok,result?,error?}`. `ok:false` remains failure through every wrapper. Duplicate results ignored.
- Client `accessibility_event`: `{seq,timestamp,type,package,class?,windowId?,text?,description?,conversationId?,droppedSinceLast?}`. Events are rate-limited and deduplicated on Android, kept in a bounded in-memory buffer and never inserted into an agent prompt automatically.
- Client `voice_partial`: `{sessionId,conversationId,text,wakePhraseArmed,timestamp}`. This is transient local-STT telemetry; raw audio is never sent.
- Client `voice_session`: `{sessionId,conversationId,event,source?,phase,wakePhraseEnabled,onDeviceRecognition,bargeInSupported,batteryAtStart,batteryNow,timestamp}` where event is `started|stopped|submitted|armed|barge_in|wake_phrase|speaking|playback_finished|send_failed`. The latest voice session is cleared when its WebSocket disconnects or is replaced; a stale session must not remain active after an app update.
- Client `ping` → server `pong`. Server errors `{code,message,requestId?}`. No plaintext command contents or secrets are logged.

Server events are persisted with a monotonic per-device `seq`; reconnect hello replays events above lastSeq (max 1000 per connection; fetch history for older state). `GET /api/conversations/{conversationId}/messages` returns `{messages:[{messageId,role,text,status,createdAt}],lastSeq}` scoped to device. HTTP `GET /api/status` returns health and mode.

## Files (Bearer auth, same TLS pin)

1. `POST /api/uploads` body `{name,mime,size,sha256}` → `{uploadId,offset,chunkSize:1048576}`. Maximum 512 MiB. SHA-256 lowercase hex.
2. `GET /api/uploads/{uploadId}` → `{uploadId,offset,size,complete}` for resume.
3. `PUT /api/uploads/{uploadId}/chunks` raw bytes, header `Upload-Offset: N`. Response `{uploadId,offset}`. Wrong offset 409. Chunk max 1 MiB.
4. `POST /api/uploads/{uploadId}/complete` → `{uploadId,offset,size,complete:true,name,mime,sha256}` after size/hash verification; mismatch 422.
5. `GET /api/files/{uploadId}` authenticated original bytes with attachment filename; only completed, device-owned files. Android-origin and PC-published files use the same ID mechanism. Original bytes are never compressed.

Server event `file_received`: `{uploadId,name,mime,size,sha256,conversationId,seq}` announces a PC-delivered file. Hermes receives the `punk_send_file(path)` tool in the dedicated profile; its middleware publishes an existing file through authenticated internal `POST /api/files/publish {path,deviceId?,conversationId?}`. No path supplied by a public device is accepted by this internal-only endpoint.

Attachment contents are untrusted data. The bridge places completed files in private storage and tells Hermes their local path; image/document handling uses the configured Hermes tools. Files are not silently uploaded to arbitrary services.

## Internal PC API

Separate plain HTTP listener `127.0.0.1:18766` only. Requires its own Bearer secret, stored in the bridge runtime config and provisioned into the dedicated plugin. Never expose this listener on LAN. `GET /api/status`, `GET /api/device-events?deviceId=&sinceSeq=&limit=`, `POST /api/tool` `{tool,params,deviceId?,callId?,timeout?:30,conversationId?}`, `POST /api/chat` `{text,role?,deviceId?,conversationId?}` support plugin wrappers. The device-events response contains the bounded accessibility buffer and latest Live voice state; its contents remain untrusted observations. If deviceId omitted exactly one paired connected device is required, otherwise 409. `POST /api/policy/check` `{tool,args,sessionId?,callId?}` blocks only the dedicated profile middleware until approval or timeout and returns `{allow,authorizationId?}`. Policy health/registration and run bindings are internal only.

Hermes upstream: `http://127.0.0.1:8642/p/punk-mobile`; `POST /api/sessions`, `POST /v1/runs`, `GET /v1/runs/{id}/events` with `Last-Event-ID`, `POST /v1/runs/{id}/stop`. The bridge owns its upstream token; Android never receives it.
